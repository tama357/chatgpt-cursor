# 作業状態の引き継ぎ

## 使う条件

ユーザーが引き継ぎを求めたとき、または長い作業で不要な履歴が増え、安全な区切りで作業状態を残す必要があるときに使う。工程数だけを理由にチャットを分割しない。引き継ぎを作るためだけに全資料を読み直さない。

## 作成・保存

- その時点で確認できた事実から、日本語で短くまとめる。会話全文・思考過程・重複説明は含めない。再試行を防ぐために必要な失敗方法や不採用理由は一行で残す。
- 既存のプロジェクト別引き継ぎ先があればそれを更新する。なければ、現在アクセスできる作業フォルダ内の `HANDOFF.md` などを使い、別プロジェクトの文書を上書きしない。
- 正本の場所、ブランチ・コミット、成果物パスは確認できた値だけを書く。不明なものは未確認とし、端末にアクセスしていないのにWindows上へ保存済みと書かない。
- 既存の許可範囲と停止条件を残す。サブエージェントは原則不使用。明示許可がある場合だけ当該作業の範囲を記録し、別作業や外部操作への許可に読み替えない。
- 投稿・送信・予約・書込みの実施有無、対象ID、照合結果を残す。実行中または成否不明なら未確認と書き、次回は状態照会を先にして二重実行を防ぐ。
- 安全に進められる依頼済み作業は続ける。引き継ぎ保存を理由に途中で打ち切ったり、新しい指示を要求したりしない。新規セッションの開始やモデル変更は、実機能と許可を確認できた場合だけ行う。

## 出力テンプレート

必要な項目だけ具体化する。ただし、承認待ち・実施有無・次の操作は省略しない。

```md
# 引き継ぎ：プロジェクト名
更新日時（日本時間）：
正本／作業場所：
ブランチ・コミット（未取得なら未確認）：

## 目的・完了条件

## 現状と成果物
完了済み／未完了を区別。重要ファイルと用途を記載。

## 決定事項・残件
有効な決定、未解決事項、再試行を避ける失敗条件。

## 検証
実行した確認、その結果、未実施・未確認の内容。

## 制約・許可・承認待ち
サブエージェントの許可有無と対象範囲、停止中処理、マージや公開の承認状況。

## 外部操作の状態
未実施／実施済み／成否未確認、対象IDと照合結果。該当がなければ「なし」。

## 次の具体操作
最初に確認・実行する操作を一つ指定。
```

## 再開時

現在の明示指示と適用されるルールを確認し、引き継ぎと直接関連するファイルだけ読む。差分・コミット・外部状態が変わっていれば該当箇所を再確認する。完了済み作業は繰り返さず、許可を拡大せずに次の具体操作から再開する。

## 完了条件

保存先を読み戻し、参照先、次の操作、未確認事項、承認境界が矛盾していないことを確認する。「文書保存」と「新規セッション開始・PC同期・実行時読込み」は別々に報告する。
