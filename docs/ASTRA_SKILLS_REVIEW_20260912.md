## 7. 制作依頼へ適用する例

以下は次回の依頼文を作る際の例であり、定時タスクを書き換えたり、今回制作・公開を依頼したりするものではない。既存の正本・形式・本数・上限を使い、未確認の設定は補完しない。実際の依頼では不要な項目を除く。

### 完成動画を依頼する場合

```text
目的：指定された本数の動画を、指定の出力形式で完成させる。
入力：今回のテーマ・素材と、作業環境にある最新の制作正本。
完了：台本や編集プランだけで止まらず、書き出した実動画について
字幕・音声同期・素材抜け・冒頭と末尾・出力仕様を確認し、問題箇所を修正する。
境界：既存の冒頭1秒・5秒、権利確認、本数・在庫上限を維持する。
予約や公開は既に許可された範囲だけ行い、実施した場合は予約後に照合する。
報告：完成ファイル、確認結果、保留理由、実際に予約したかを分けて示す。
```

### 漫画の完成巻を依頼する場合

```text
目的：採用済み基準稿と指定ページ数に沿って、1巻を読める形に完成させる。
入力：基準稿、人物正本、進行中のページ、既存の出力仕様。
完了：構成・ネーム・優先ページだけで終了せず、指定全ページを揃えて書き出す。
ページ抜け、文字欠け、コマの読む順序、人物・衣装・設定の一貫性を確認して直す。
境界：基準稿と採用済み設定を無断変更しない。公開・販売は別の許可範囲。
報告：完成ページと未完成ページを明示し、未確認の作画を合格扱いにしない。
```

### 記事を依頼する場合

```text
目的：指定読者に向けた、指定文字数・形式の記事を完成させる。
入力：依頼条件、本人の事実、今回必要な一次資料。
完了：本文の執筆、文字数計測、事実確認、自然な日本語への修正、指定先への保存。
境界：体験を捏造しない。医療効果や収益を保証しない。納品送信は許可範囲のみ。
報告：本文、文字数の数え方、保存先、残る未確認事項を示す。
```

## 8. 利用を確認する順序

GitHubブランチへの保存、承認後のmainへのマージ、対象PCへの同期、対象アプリでの検出・読込み、実タスクの品質比較を別々に確認する。公式Build skillsのローカル配置は `.agents/skills/` だが、GitHubに置くだけで全てのChat / Workへインストールされたとは報告しない。
