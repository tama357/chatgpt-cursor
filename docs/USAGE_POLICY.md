# 利用量を抑える作業方針

更新：2026-09-13。利用量の見直し・モデル選定・設定監査が必要な場合だけ読む。これは作業指示であり、アプリ設定を変更する実行ファイルではない。

## 優先順位

ユーザーの明示指示、既存の承認境界、成果物の品質・安全性を守ったうえで、不要な読み込み・再実行を減らす。料金や利用枠の削減率は実測なしに断定しない。

## 単独実行を標準にする

- サブエージェントは原則使わない。当該作業についてユーザーが明示的に指示・許可した場合だけ使用する。
- 「全部任せる」「効率化して」「最後まで自動で」、大量作業、難しい作業は許可に含めない。別の依頼での許可を引き継がず、スクリプト・外部ワーカー等で子エージェントを起動して迂回しない。
- 許可された場合も、目的・必要な入力・対象ファイル・制約・出力・完了条件に絞った自己完結する依頼を渡す。親の会話全文を既定で複製しない。実環境の対応を確かめ、未確認の設定キーやモデル名を作らない。

## 読み込みと確認を絞る

- 適用ルールとタスクを確認し、必要なスキル・ファイル・ツールだけ段階的に読む。所在が不明なら検索し、関連する部分から広げる。
- 同じ版の同じ資料・検索結果を理由なく取り直さない。更新の可能性、情報不足、修正後の検証がある場合は再確認する。
- 小変更は差分と影響範囲を確認する。未変更部分の全体テスト、全素材再生成、同じ失敗条件での再試行を増やさない。既存テスト方針と必要な品質確認は省略しない。
- ツールが利用できないと確認したら、同じ呼出しを根拠なく繰り返さず、できた範囲と制約を報告する。
- 安全に使える既存のスクリプトや編集部品は再利用する。停止中の予想処理・テストを再利用の名目で実行しない。

## モデルと推論強度

- ユーザー指定と実際に選択中のモデル・設定を尊重する。文章にモデル名を書いただけで切り替わったと扱わない。
- 新しい作業で選択可能な場合は、必要な品質・ツール対応を満たす負荷の小さい選択肢を検討する。単純修正だけのために新規セッションを起動しない。
- 高い推論強度・高速モードを「念のため」常用しない。必要な能力が不足したときは理由を明確にし、対応機能・権限・費用への影響を確認して変更する。品質を損なう一律の低設定も強制しない。
- 長い会話の途中での頻繁な切替は避ける。ただし、モデル・推論強度変更のたびに新規セッションが必須とはしない。実環境のキャッシュ・圧縮対応と引き継ぎ負担を含めて判断する。
- 契約変更、追加クレジット購入、有料API呼出し、ユーザーの設定の一律変更は、この方針だけでは許可しない。

## 引き継ぎと制作

引き継ぎが必要なときは [session-handoff](../.agents/skills/session-handoff/SKILL.md) を使う。短い会話や小変更まで分割しない。引き継ぎの作成だけで依頼済み作業を止めず、ホストの既存のコンテキスト圧縮を勝手に無効化しない。

動画は企画・台本・素材確定、制作、最終出力確認などの安全な境界を候補にする。ただしレンダリング中や投稿・予約と照合の間は機械的に分断しない。既存の本数・在庫上限、音声設定、権利確認、最終出力の再生確認、予約後照合を弱めない。漫画は正本・確定設定・制作済みページ・未修正箇所を残し、全巻や全ページを理由なく再生成しない。

## Plugin / MCP

必要なツールを必要なときに読み込む。インストール数だけから消費原因を断定せず、実際に投入される定義や利用ログを確認する。削除・接続解除・一括無効化・認証変更は行わない。設定変更が必要なら、対象機能、他の作業への影響、対応する正式設定を確認し、既存の承認境界に従う。

## 効果の確認

通常の作業で取得できる場合だけ、作業内容、モデル・推論強度、利用前後の残量と時刻、再実行回数、品質上の問題を記録する。表示がなければ未取得とする。途中のリセットや他セッションの消費を区別し、単発の変動を削減効果と断定しない。比較のためだけに有料処理や大規模制作を二重実行しない。

## 根拠と、前の提案から修正した点

ユーザー提供の「GPT-6 Astra usage limit problem」文字起こしから、必要な文脈への絞り込み、短い引き継ぎ、不要な高負荷処理を減らす考え方を採用した。モデル別の節約率や投稿者の体験は、この環境の実測値・公式な利用枠計算式として採用していない。

2026-09-13に次の公式資料を確認した。資料の一般仕様と、このリポジトリでの動作確認は別である。

- [Build skills](https://learn.chatgpt.com/docs/build-skills)：必要なときに本文を読む構成と、SKILL.mdのname / descriptionを採用。
- [Rethinking skills and prompts for GPT-6 Astra](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra)：適用範囲を絞り、無関係な資料や過剰な手順を常時読ませない構成を採用。
- [Prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching)：共有される先頭部分の再利用を扱うAPI仕様。要約・圧縮・設定変更で再利用条件が変わり得るため、「毎工程で新規セッションにすれば必ず節約」「推論強度変更は必ずキャッシュ失敗」という前の断定的な運用案は採用しない。API料金をサブスクリプション利用枠へ直接換算しない。
- [Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents)：子エージェントも独自にモデルとツールを使う。機能が提供されていても、ユーザーの明示許可なしには使わない。

`fork_turns = none` は、前の会話の例をそのまま汎用の正式設定値として書き込まない。今回の変更はAGENTS.mdとスキル等の指示文であり、子エージェントの起動をシステム設定で強制遮断したものではない。
